## 2026-10-06 增补（K/L 落地后：旋钮换过一轮，枚举收窄过一次）

**核对方式**：脚本遍历 `CONFIG` 全部叶子键（**109 个**）× 全部 `cfg()` 调用点
（**124 处**，落在 **80 个**不同的键路径上），再逐条读注释。本轮改动**逐条过**：

- ✅ **新增 5 个旋钮都有精确读点**：`recall.signal_votes`（`multi_hit`）·
  `recall.literal_max_df` / `recall.literal_max_words`（`_literal_hits`）·
  `memo.soon_hours`（`memo.due`）· `prompt.fixed_budget_chars`（`prompts.fixed_blocks_report`
  → 预算测试 + 设置页）。**没有一个新的"配置在说谎"。**
- ✅ **删掉的 3 组没有残留读点**：`recall.multi_hit_k`（→ 票制 `signal_votes`）·
  `rank.w_recency`（→ 排序四键的"新鲜度"，`recall.order()`）· `memo.proactive.*`
  （主动开口整块删除；`soon_hours` 提上来单列）——原位都留了"已删 + 理由"的注。
- ✅ 数字仍只写一处：四处兜底值与现值一致（`fixed_blocks_report` 2200 / `multi_hit` 3 /
  `_literal_hits` 3 / `memo.due` 4）；前端新增的票数行与「到点了」标**都从后端值渲染**，
  没抄阈值。**既有挂账照旧**：`web/index.html` 的 `20000` / `6000`（见上）。
- ✅ 枚举收窄：`MEMO_TIMINGS` 从四值收到两值，schema 仍引用 model 常量（`list(MEMO_TIMINGS)`）、
  prompt 散文同步；老库里的 `result` / `after` 无读点也不报错。
- ✅ null / 0 的口径没破：本轮新数据用**存在性**表达（`due` 标记有/无），
  `votes: 0` 是"真计数"不是"算不出来"（见 L7 那两条）。

**本轮修掉的 6 处**（都是"注释/常量与代码不一致"这一类的）：

1. `prompt.fixed_budget_chars` 与 `memo.check_interval` **漏标 `*`**——两个都是调过的阈值
   （2100→2200、3600→600），按本文件约定必须标"要实测标定"。
2. `recall._LITERAL_MAX_WORDS`（=3）**写在业务代码里**——违反 config 模块头那句
   "可调参数集中于此"；已搬为 `recall.literal_max_words`（标 `*`）。
3. `MEMO_TIMING_SOON / MEMO_TIMING_LATER` **建成员常量**：`memo.due()` 原来是裸字面量
   `== "soon"`，改名/改字面就静默失效（同 `MEMO_PENDING` / `INVALIDATED_*` 的处理）；
   `later` 无读点，已按 `MEMO_STATUS` 的先例注明。
4. `model.Memo.timing` 的注释"空 = 未判，**按原判定走**"——"原判定"（时机表 / `should_raise`）
   已删；改为"按常规窗口走"。
5. `model.MEMO_CLASSES` 上方 followup 的注释还在说"走「到点该提」/ 沉默时主动开口、
   不挂在常备栏每轮刷"——那两条路已删；改为现状（到点进注入一次、进即记账；
   没到点的只在"相关 / 最近"里兜底出现）。
6. **`config.py` 里两处空引用**（这轮核查才发现的）：模块头写着"本文件是**设计稿
   CONFIG 块**的代码化，字段顺序与文档保持一致"、CONFIG 上方写着"所有 `*` 参数初值的
   出处：设计稿的 CONFIG 块"——**那份 CONFIG 块不存在**：记录里键名与初值是**散在各篇
   散文里**的（`literal_max_df`、`rank.recency_halflife_days`、
   `config.prompt.fixed_budget_chars` …），既没有集中的清单，"字段顺序与文档一致"
   更无从谈起。已改为实际关系：**理由在记录那一段、数字的权威在 config 这一处**
   （记录顺手会点键名与初值，对不上时以 config 为准）；`*` 的含义（没标定过的初值）
   也写在同一行旁边。（2026-09-25 那轮把这里"补成"了 `设计稿 CONFIG 块`，
   方向反了——补的是一个查不到的目标。）
   另：新旋钮 `recall.literal_max_words` 已补进记录（唤醒层 §五 字面旁路 + 待确认 6，
   那条从"三个数"改成"四个数"）——**键名要能被记录点到**，这是"记录讲理由、
   代码讲值"的一半。
