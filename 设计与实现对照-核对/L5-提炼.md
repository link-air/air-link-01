### 体检与复核（2026-09-23 加，设计稿 记忆整理行为 §四/§五）

- [ ] 体检**复用不复制**：`maintenance_cycle()` = `run_distill_cycle(topic_cap=)`（①零成本维护 +
      ②主整理封顶）+ `review_profiles()`（③）+ `write_maint_trace()`
- [ ] **会话边界整理不封顶**（不传 `topic_cap` = 全量）——体检是兜底，不是替代
- [ ] `topic_cap` 按「未覆盖的新场景数」从多到少花钱（`_busiest_topics`；并列按名升序，可复现）
- [ ] 复核对象只有 `established` 且距 `last_review_at` ≥ `review_min_days`（空 = 从没复核，最优先）
- [ ] 打分 → 动作（**系统永不硬删**——人的否决是另一回事：真删）：`holds` **什么都不做**（尤其**不 bump `last_support_at`**
      ——复核 ≠ 印证，bump 了 90 天老化永远不触发）/ `thin`·`stale` 降档 pending
      （**不填 `invalidated_at`**）/ `reword`（2026-09-23 补）走**修正**
      （`revise_profile`，`by="revision"`，新版回 pending；写法判据 = `PROFILE_STATEMENT_RULES`）
      / `wrong` **只记提议**（`profile_reviews`，handled=0）
- [ ] **可算的判据归代码**（2026-09-23）：`_gate_recheck`（四道关可算部分：印证数 /
      sources / 同情境 / 跨来源）在进模型前复查——不过的**当场降档、不调模型**
      （记 `regressed`，与她的 `downgraded` 分开）；`converge_detail` 与复核**共用这一份**
- [ ] 给模型的判据只有**语义 3 条**（依据撑不撑得住 / 写法 → reword / 时间 → stale）
      + 防误判两条（多情境不是矛盾 / 只判句子与依据之间）
- [ ] 降档与重写**共享改动预算**（`review_downgrade_cap`）；`reword` 没给改写 = 当没复核过（不写 `last_review_at`）
- [ ] 防抖三件：`review_cap`（一次看几条）/ `review_downgrade_cap`（一次最多降几条，防集体误判）/
      认不出的打分当没复核过（连 `last_review_at` 都不写）
- [ ] 复核材料带**依据**（`evidence_pack` 快照；空则现查 `sources` 场景标题）——只给陈述等于凭印象打分
- [ ] **空闲零调用**：库空 / 无新素材 / 无空缺时，体检一次模型都不调（`test_phase7.py` 钉住）
- [ ] 复核的**逐条打分 + 理由**进返回值（`details`）→ 留痕带着落盘；
      `profile_reviews` 另有 `reason` 列（状态与日志各一份）
- [ ] **提议清理只有一处**：`store.delete_profile`（随画像一起删）——界面「不对」按钮
      （`/api/reject`）/ 她提 `forget_memory` 他点（`weave.delete_by_layer`）两条入口共用
      （分开写会漏一条；原 `reject_profile` 工具 2026-09-24 已并入 `forget_memory`）；
      `maint_reviews()` 另有一层兜底（画像已不在 / 旧库作废行 → 列提议时顺手标掉，自愈）
