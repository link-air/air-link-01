**这层是干嘛的**：把一段对话变成一张场景卡。写入单元是**话题段**不是单条消息；
**切场景与提取触发是同一个判断**。

**去哪核对**：`scene.py` 的 `should_cut()` / `extract_scene()` / `is_trivial()`；
`entity.py` 的 `link_entities()`（消歧口 `store.find_entity()`、人工合并口 `store.merge_entities()`）。

- [ ] 切场景与提取触发是同一个判断（不另设机制）
- [ ] 切分判据 `> max(mean + γ·std, min_distance)`——两个保险都在：绝对下限 + 最少样本数；
      降级（无向量）走**另一条判据**（`should_cut_texts` + `cut.min_distance_text` 0.93）
- [ ] `trigger_class` 不在七类里 → 空串，不猜
- [ ] 入库向量来自「标题 + 关键词 + 摘要」拼的**检索文本**，不是整段原文
- [ ] 时间**不由 LLM 抽**（取记录时刻）；用户**明说**的时间转绝对日期——见 L8 的 `due_at`
- [ ] **纯寒暄不会变成场景卡**，且跳过有留痕
- [ ] 判定失败一律**当"值得存"**；`worth_saving` 与字段抽取**同一次调用**；
      「像不像画像素材」**不是**判据（他提到的人和事同样值钱）
- [ ] 跳过 ≠ 当没发生：模型判的**照留摘要**，代码判的（寒暄）摘要也不留；
      **两种跳过都留痕**（`data/trace/跳过-*.jsonl`）
- [ ] **实体只记和用户有个人关系的**（2026-09-25）：抽取层（`prompts._SCENE_PROMPT`
      + `scene._norm_entities`）与写入层（`entity.link_entities`）各有一道闸，
      **没 `relation` 不建不挂**；公共人物 / 事件 / 技术名词 / 话题词不进索引
- [ ] 实体消歧保守：**精确匹配 name / aliases（大小写不敏感），不做自动语义归并**（`find_entity`）
- [ ] **人工补救口是通的**：实体页「并到…」→ `POST /api/entity-merge` →
      `weave.merge_entities_confirmed` → `store.merge_entities`——只改归属、不删场景；
      **旧名字并成别名**；留痕；不可撤销
- [ ] ⚠️ 合并的坑：`scene_entities` 复合主键——「两个实体挂同一条场景」时走
      「先 `INSERT OR IGNORE` 复制、再删旧行」（重复那条被忽略，正是想要的）
- [ ] 强度是**行为信号**（字数 / 重复 / 追问），不靠 LLM
