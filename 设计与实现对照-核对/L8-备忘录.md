**这层是干嘛的**：`open_loops` 的可提醒子集。四条纪律（同 `memo.py` 模块头那份清单）：
**时间只抽他明说的那一处** / **到点进注入一次、提过就停** / **只有硬隐私不进注入** /
**退役只管"不再提醒"**。

**名字**（2026-09-22 统一）：`open_loops` **只指场景卡上的字段**（钩子）；这层数据
在界面 / 文档 / 工具里一律叫**备忘录**（`memory_search` 的 memo 层 / `close_memo`）；进注入那一路
叫 `standing_memos`（`recall` 结果里的键同名）。

**去哪核对**：`classify_window_kinds()`（只分类）、`classify_group_names()`（补组名）、
`due()`（到没到）、`standing_memos()`（进注入的那一栏）、`_group_raised()`（一件事只提一次）、
`judge_hits()` / `hit_candidates()`（命中判定）、`retire_due()`（退役）。

- [x] 不出现"由模型估的天数"——模型只分类（类别 + 时间锚），窗口由系统映射
      （`config.memo.window_defaults`；状况类的 `soon` 用 `memo.soon_hours`）
- [x] `due_at` 只在用户**明说了时间**时才有值
- [x] **到点 = 有资格进注入**（2026-10-05 晚）：`due()` 只回答"到没到"——
      不再有**时机表**、不再有"此刻自不自然"的判定（两者连同 `should_raise()` /
      `raise_candidates()` 一起删了）；提不提、怎么提是**提示词里的分寸**
- [x] **到点进注入一次，提过就停**：`standing_memos()` 正常轮挑
      **到点 1 + 相关先挑满 + 最近补位（≤2）**、封顶 4；**到点那件带 `due` 标记**；
      `full=True`（他追问指代）时全列、封顶 8
- [x] **进即记账**：`chat._mark_memos_raised()` 认 `standing_memos` 里的 `due` 标记 → 标 `raised`
      ——**下一轮不再进那一栏**；**被预算裁掉的不算"提过"**（下轮还要能再进）
- [x] **一次一件**：两件同时到点也只给一件（其余没记账，下一轮接着排）——
      一次端三件就成清单了
- [x] **`followup` 不再单独排除**（2026-10-05 晚）：它跟别的 memo 走同一条
      （到点进一次、进即记账）
- [x] **只有硬隐私不进那一栏**（`sensitive >= 2`：创伤 / 家事窄名单）；
      感冒、体检照进——点出事情本身是给门、不是揭开
- [x] `raised` 的**不进常规轮**（提过一次就不再提）；`full=True` 照旧全列——
      「不再主动提」不等于「可以忘掉」
- [x] 提醒分寸写在渲染侧：**给门不端细节 / 一次一件 / 问过程不问结果**，
      以及「哪件做完了顺手 `close_memo` 关掉」——都注在【你手上还挂着的事】那一栏
      （`prompts.render_memory_block()`）
- [x] **接上唤醒**（2026-10-05 晚）：备忘录**跟着它的场景卡走**——卡被注入时那行
      「→ 未定：…」跟着露出来（`prompts.scene_line` 拼行、判据在 `prompts._pending_of`：
      闭合 / 退役的钩子都跳过）；**`raised` 不挡它**（"不再主动提" ≠ "可以忘掉"）；
      到点与"手上得有"是**同一栏**（【你手上还挂着的事】），栏内三个来源
      （到点 / 相关 / 最近）按 **memo 编号**去重（`standing_memos.add()`）——
      **跨栏不去重**：卡上那行与栏里那条可以同时出现（一个是卡上钩子、一个是备忘条目）；
      **没有卡的 memo**（打捞重建认不到卡的）只剩"到点"一条通道——量小先跑着看
- [x] **她从不主动开口**（2026-10-05 晚）：主动开口整块删了——`proactive_open()` /
      `openings` 表（退役留底 `openings_retired`）/ 安静时段 / 沉默判定 / `开口-*.jsonl`；
      她的话只发生在他说话之后
- [x] **退役**（`retire_due`，2026-10-05）：判的是**提的窗口**——
      起点 `due_at` 或 `created + window_days`，+ 2 天仍未提 → 退役；
      `raised` 的另有**超期未回**（`raised_at` + 3 天）
- [x] 退役**不回流**：钩子标 `retired_at`（**不是** `closed_at`——退役 ≠ 完成），
      渲染侧两者都跳过（`prompts._pending_of`）；退役写留痕 `by="超期退役"`——
      四个关闭发起方**都有留痕**（原来退役这一路是唯一没有的）
- [x] 状态机**单调**：`mark_memo_raised` 只对 `pending` 生效——同一轮里
      「进了注入」又被这句话了结的那条**保持 `closed`**，不会被打回 `raised`（回执也不报）
- [x] air 的**客套话不当承诺**（`is_pleasantry()` 兜底）
- [x] **命中判定**（`judge_hits`，2026-10-05；词表 `_CLOSURE_MARKS` 已删）：本条消息命中的
      每件挂着的事判一个动作 `none` / `update` / `close`；**提到 ≠ 了结**（给 `none`）；
      判不准 / LLM 不可用 = **什么都不做**
- [x] 命中粗筛**不用字面**（`hit_candidates`）：条数 ≤ `hit_full_n` 全量；超出按相关度
      （场景向量 + `char_overlap` 降级）取前 `hit_top_n` + **刚提过的**（`raised_at` 在
      `hit_grace_minutes` 内）；判定走**全量 open memos（含 `raised`）**
- [x] 命中判定**只对 `user` 的话判**（air 自己的话不替用户了结；她的承诺走 `close_memo`）
- [x] `update`（变更）：内容换掉、**回 `pending`** 并清 `raised_at`、
      窗口按新内容重映射；`due_at` **只在用户明说时**写（铁律不破）；留痕记「旧 → 新」
- [x] **同一轮"进过注入 + 又被变更"的不记「已提」**（`chat._mark_memos_raised` 比对
      注入时内容与库里内容；不然新内容永远没机会再进注入）
- [x] `loop_id`（2026-10-05）：钩子编号**由代码生成**（`store.add_scene`，形如 `S1-0042#2`）；
      闭合 / 退役按它定位，**老数据退回 `content` 全等**（不报错）
- [x] 闭合有**留痕 + 回执**（2026-09-22 补 · 2026-10-05 补全）：**四个发起方都有留痕**
      （`备忘-*.jsonl`，含"谁关的"——命中判定 / 她调工具 / 用户随手划 / 超期退役；
      前三个共用 `memo.close` 那一份，退役自己写一份）；
      命中判定的结果随**那一轮回执**回来（`memo_closed`：编号 + 内容），
      **只报一次**（`take_closed_memo` 读后即清）
- [x] **名字各归各位**（2026-09-22 统一）：界面 / 文档 / 工具一律「备忘录」；
      `open_loops` 只指场景卡字段；进注入的函数与 `recall` 键都叫 `standing_memos`
- [x] **组（`group_name`）只用于呈现与提醒收拢**（2026-09-22）：闭合仍逐条；"一件事只提一次"
      （组内有 `raised` 则其余步骤**不进注入**，**提过之后新出现的步骤除外**）；**不做合并**
      （合两条会踩定位、也让"一件事"的边界变糊）
- [x] **`content` 可以变，但只走 `update` 动作**（2026-10-05 改）：匹配键已经是 `loop_id`
      ——`content` 不再承担"定位钩子"的职责（**老数据没有编号，仍以 `content` 全等兜底**，
      见上条），所以"变更"是安全动作；
      它**只由命中判定显式发起**（带留痕），没有任何地方做隐式改写
- [x] 空组名由会话边界补判（`memo_cycle` → `classify_group_names`）：只填空的、
      **已有的不动**、全都有组名时不调模型
