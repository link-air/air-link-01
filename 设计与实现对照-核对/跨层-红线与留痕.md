**红线**（这些是"明确不做"，不是"还没做"）：

| 不做 | 为什么 |
|---|---|
| 用代码硬保证「不迎合 / 不诊断」 | 做不到，只会写出一堆无效逻辑——交给对话层 |
| 自动合并主题 | 合并是不可逆的语义断言，不该由代码替用户下 |
| 自动替用户决定「你需要被分析」 | 那是诱导 |
| 把敏感做成"不召回" | 召回是理解的前提，敏感只调节**说出口的力度** |
| 让模型估天数 | 时间感不可靠，只分类、由系统映射 |
| **静默**删改记录 | 红线防的是静默丢失，不是主动清理——归档 / 老化只标记、**可逆**；要删只有人能发起（真删 = **删一行**，"要不要后路"由人在确认条上选） |

| `整理-*.jsonl` | 体检：为什么跑（累计字 / 距上次小时）、三档各做了什么、复核逐条打分与理由（2026-09-23） |

**一条贯穿所有层的原则**：凡「本可以发生但决定不发生」的分支（跳过 / 拒绝 / 没提 / 放弃），
**要么 `print`、要么落 trace**——静默的不作为是这类系统最难查的故障。
